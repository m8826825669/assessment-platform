# Project working rules
Read docs/MASTER_ROADMAP.md, docs/PROGRESS.md, docs/DECISIONS.md and docs/BACKLOG.json before changes. Follow milestone dependencies. Link work to requirement IDs. Do not broaden scope silently. Never mark database, API, UI, concurrency or production behaviour verified by domain unit tests alone. Update progress and evidence after every increment. Preserve tenant boundaries, immutable publications and server controlled timing. Published scoring keys never enter candidate payloads. Do not deploy without explicit production release approval.

For current identity/membership mutations, audit and outbox records must commit with business changes. Use app.audit.service.record with registered actions and explicit safe snapshots; it must not commit independently. Never serialize passwords, tokens, emails or arbitrary ORM/request bodies into snapshots. New business modules must extend the registry and rollback tests explicitly.
Use RFC 9457 problem responses and server-generated request UUIDs. Readiness is a documented diagnostic exception to the problem envelope. Background processing uses a separate restricted worker role, fenced leases and unique local receipts. The current consumer is local only; do not add external effects, fanout or ordering guarantees without a recorded design change and destination-specific idempotency tests.

P1 is accepted with owner-supplied evidence in docs/P1_ACCEPTANCE.md. P2 work follows docs/P2_QUESTION_BANK_PLAN.md and BACKLOG.json. Candidate rendering must use the explicit question-content public projection; never return the authoring model or private rubric/key material. Content unit tests do not prove persisted version immutability, authorization or media safety. New content schema behavior requires explicit schema/hash compatibility review. Close each bounded increment with strict local and actual CI evidence before its dependent task.

P2-001 is accepted in docs/LOCAL_VERIFICATION_P2_001.md. P2-002 saved drafts must preserve immutable question_versions and stable originating authorship. Every save advances exactly one fenced revision and appends a snapshot/audit/outbox atomically. Do not edit an old version or add approval by changing its content. Honor own-author/admin draft access and post-lock authority rechecks. P2-003 must add independent review as separate state/decision records, with no self-approval and explicit role/RLS updates. Read docs/QUESTION_BANK_API.md before extending these routes.

P2-002 is accepted in docs/LOCAL_VERIFICATION_P2_002.md. For review work read docs/QUESTION_REVIEW_API.md. Review event history is immutable; origin/editor/submitter cannot approve or return their own exact version. Edits supersede pending reviews atomically; never transfer approval. Coordinator reads use question_selections public snapshots, never private version models. Keep the SQL and Python public allowlists aligned for schema v1 and test all types. Retire only through an auditable event and guarded selection update in one transaction. P2-003 is accepted on owner evidence in LOCAL_VERIFICATION_P2_003.md.

P2-004: read docs/TAXONOMY_API.md. Classification belongs to immutable version creation, with SQL-derived snapshots and transaction fencing; never append historical links or rewrite saved labels. Keep original body-hash schema; version identity binds metadata/review. Queries must filter before pagination and preserve existing role boundaries. P2-004 is accepted on owner evidence in LOCAL_VERIFICATION_P2_004.md.

P2-005: read docs/MEDIA_API.md. Keep quarantined/rejected/unavailable bytes out of previews, approvals and selections. Freeze media descriptions and exact object versions; never fall back to latest storage bytes. Extend only explicit safe projections and registered audit metadata. Strict verification now needs dedicated real storage/ClamAV consent and services; fake gateway tests do not close the live gate. Production storage/retention/support remains separate.

P2-005 is accepted on owner evidence in LOCAL_VERIFICATION_P2_005.md. P2-006: read QUESTION_IMPORT_API.md. Preview must not persist business/audit rows. Never commit individual rows inside a batch. Keep actor-scoped immutable success receipts and atomic question/version/reference/audit/outbox writes. Replay acknowledges original durable creation; recheck current actor authority before lookup but do not recreate prior data when references retire. Raw import rows/keys never enter logs/audit. P2-006 remains pending strict new local/CI evidence before browser work.
